# Lattica Theme Sandbox and Execution Boundary

## Status

Planned runtime safety contract for theme previews, sample cards, and verified installs.

## Purpose

Prevent theme packs from executing code or escaping data-only boundaries.

## Core Rule

Themes are data, not programs.

A theme pack must never contain executable behavior.

## Runtime Boundaries

Themes may affect approved theme token values, approved UI preview metadata, approved static assets, approved sample-card render data, and approved motion-safety metadata.

Themes may not affect commands, hotkeys, filesystem, network, app settings outside theme scope, plugin system, scripts, arbitrary CSS, renderer internals, graph/Sigma mutation, audio input/playback, camera movement, or animation unless separately safety-approved.

## Preview Sandbox

Theme sample cards render in a sandboxed preview environment.

Required restrictions:

- no scripts
- no network
- no external URLs
- no inline event handlers
- no iframe escape
- no local file access
- no command execution
- reduced motion default
- animation disabled unless preview asset is a static approved GIF/WebP
- strict size limits
- memory/time limits
- strict CSP
- no access to user project data
- no access to secrets/tokens

## Preview Asset Rules

Allowed: static PNG, static WebP, bounded GIF/WebP animation only if motion-safe, markdown description text, structured preview JSON.

Forbidden: HTML preview code, JavaScript preview code, iframe content from theme, remote images, remote fonts, CSS imports, and SVG initially unless sanitizer/renderer is approved.

## Download Button Boundary

A “download theme” button must not directly run arbitrary commands.

Allowed: call internal verified installer, install catalog artifact by ID/version, verify signature before install, show command copy text generated by Lattica, and stage install before apply.

Forbidden: executing shell commands from theme metadata, executing repo-provided scripts, letting theme define install command, unverified pull from arbitrary repo URL, automatic install on preview click, and postinstall hooks.

## In-App Terminal Boundary

If Lattica includes an embedded terminal:

- no theme pack may write commands into it
- no theme pack may auto-execute commands
- command templates must be app-defined
- user confirmation required
- command allowlist only
- install process verifies artifact before applying
- terminal output must not be trusted as theme validation evidence

## Install Boundary

Themes install only into controlled theme directories.

Install process:

```txt
verified artifact
→ staging directory
→ manifest re-check
→ hash re-check
→ allowed paths only
→ apply safe tokens/assets
→ write install record
```

Forbidden: writing outside theme directory, modifying source files, modifying config outside theme scope, writing scripts, modifying package files, changing permissions, or spawning processes.

## Motion Safety Boundary

Theme preview/install must respect motion safety: reduce motion default in sandbox, motion risk metadata required, high-risk animation forbidden unless separately contracted, strobe/flash/high-frequency flicker forbidden, and animated preview assets reviewed/scanned.

## Graph/Sigma Boundary

Theme packs cannot directly mutate Sigma renderer, Graphology graph data, node attributes, edge attributes, canvas/WebGL internals, graph physics, or camera state.

Any future graph visual application must pass through a separately contracted Lattica runtime layer.

## Acceptance Criteria

A sandbox/execution boundary is acceptable only when theme content cannot execute code, preview cannot access network/filesystem, install cannot write outside controlled directories, theme metadata cannot define commands, sample cards cannot load remote assets, motion safety is enforced, and renderer internals are protected.
